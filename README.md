# Лист у майбутнє

Сервіс, що зберігає листи і надсилає їх адресату через задану кількість років.
Користувач пише лист собі чи близькій людині, обирає дату відкриття — через рік, п'ять чи двадцять років — і лист «спить» у сховищі до цього дня.
До дати відкриття вміст листа зашифрований і недоступний нікому, навіть адміністраторам сервісу.

## Ключові функції
- **Написання листа** — текст і вкладення, вибір адресата (e-mail) і дати відкриття
- **Капсула часу** — лист шифрується при збереженні і не може бути змінений або прочитаний до дати відкриття
- **Доставка в день відкриття** — планувальник надсилає адресату посилання на лист у призначений день
- **Підтвердження адреси адресата** — перед збереженням листа адресат отримує запит на підтвердження e-mail
- **Журнал подій** — автор бачить, коли лист створено, підтверджено і доставлено, без доступу до вмісту

## Стек технологій
- Python 3.12, FastAPI
- PostgreSQL
- Celery + Redis (планувальник доставки)
- pytest
- GitHub Actions (CI/CD)

## Секрети і конфігурація
Секрети не зберігаються в коді: модуль `src/letter/config.py` читає їх із змінних середовища і зупиняє застосунок із поясненням, якщо обов'язкової змінної немає. Значення секретів ніколи не друкуються.

| Змінна | Обов'язкова | Де взяти значення |
|---|---|---|
| `FUTURE_KEY` | так | ключ шифрування листів (блок `-----BEGIN FUTURE KEY----- … -----END FUTURE KEY-----`); видає відповідальний за сховище ключів, у продакшні — з KMS / Vault |
| `DATABASE_URL` | так | рядок підключення до PostgreSQL |
| `APP_ENV` | ні | `development` (за замовчуванням) або `production` |

Локальний запуск:
```bash
cp .env.example .env          # заповніть значення; .env ігнорується Git
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest
```

Хуки, що не дають закомітити секрет (Gitleaks з правилом для `FUTURE KEY`, detect-private-key та ін.):
```bash
pip install pre-commit && pre-commit install
```
